## 原文记录

### 1. OpenClaw 核心功能与优势
- 统一消息通道：WhatsApp / Telegram / Discord 汇集处理
- 系统级操控：执行 Shell 命令，调用服务器程序，自动修复依赖
- 持久化记忆：重启后仍记得用户身份和历史背景

### 2. 安全漏洞：模型安全 ≠ 系统安全
- **提示注入测试：失败**（AI 模型安全对齐好，三种注入方式均未受骗）
- **恶意脚本测试：成功**（伪装成"迁移检查"的 Python 脚本成功窃取 Telegram Token）
- **根本原因：默认关闭沙箱（Sandbox）**，脚本以用户权限直接在系统运行

### 3. 三大安全隐患
1. **默认配置风险**：沙箱默认关闭，代码直接以用户权限执行
2. **Skill 供应链风险**：Skill 市场约 12% 包含恶意代码
3. **安全审计局限**：自带审计工具覆盖面不足

### 4. 经济成本风险
- 24/7 运行产生无感知 Token 消耗
- 逻辑死循环可能一晚烧掉数十美元
- **建议：务必设置 API 日限额和月限额**

### 5. 最终建议
适用人群：懂系统管理和安全意识的技术极客
部署三要素：
1. 开启沙箱
2. 锁定 API 预算
3. 严格审计每一个 Skill

**比喻：OpenClaw 像脱壳期的龙虾——爪子锋利但外壳未硬**
