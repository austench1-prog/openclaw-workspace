## 2. 逐步路径（含依赖 + 验收标准）

### STEP G — 验证远程 GUI 能力（前置，最先做）
- **做什么**：确认 Dragon 能否远程操作温总PC的 NinjaTrader 界面（下数据/读指标/看回放）。
- **怎么做**：先查已有 AnyDesk SOP(2026-OPS-001) → 确认温总PC AnyDesk 可用/可连。
- **依赖**：无（最前置）。
- **验收**：✅ Dragon 能看到并操作温总PC的NT界面（或确认替代方案）。失败→退回"Chairman手动操作+截图"模式。
- **为何最先**：D 和 B校准都依赖它；不解G，后面卡。

### STEP B — 决策树 → ATM 参数反推（地基）
- **做什么**：从37叶决策树抽出每条路径"剩几手+各手冲哪个TP/盈亏比"→ 翻译成ATM Brackets参数。
- **怎么做**：Dragon读模型(discount-zone spec + 决策树) + 写反推脚本/对照表。先出"参数反推表"给Chairman审。
- **依赖**：A(已有模型) + 止损80/30(已定)。
- **验收**：✅ 4套模板各自的Brackets参数表，每个数字能追溯到决策树某条路径(不是拍脑袋)。Chairman审过。
- **关键**：这是补今天占位版缺口的根。B不对C全错。

### STEP C — 重做 4 套 ATM 模板（2×2）
- **做什么**：按B的反推参数，写出4套模板XML：{1:5策略,完全按图纸1:1}×{15M/80,1M/30}。
- **怎么做**：Dragon写XML→推温总PC AtmStrategy目录→NT重启识别→Chairman下拉确认可选。
- **依赖**：B(参数) + G(推送已可用SSH,无需GUI)。
- **验收**：✅ 4个模板都在NT下拉可选 + PC实读参数与B反推表一致(数量对账)。覆盖今天的占位版。

### STEP D — 回放测试（Market Replay）
- **做什么**：用历史数据回放，验证4套模板在真实走势下表现，出Pass/Fail。
- **怎么做**：
  1. 事先在90天内找"有80点止损+目标空间"的好测试日(高波动日)。
  2. NT Connections→Playback→下载那几天Market Replay(连续日连续下,趁早下防过期)。
  3. Playback Controller 时间跳到测试时段→选对应ATM模板手动挂单测试。
  4. 记录每套模板表现 → Pass/Fail。
- **依赖**：C(模板) + G(下数据/操作回放界面)。
- **验收**：✅ 4套模板各有回放测试记录 + Pass/Fail结论。Fail的→修正回B/C再测。
- **坑预案**：数据下了存本地就能play(合约到期不影响已下的);跳着下会断。

### → 通过后：进三步骤验证法第①步（尼家模拟账实盘验证）
- D 全 Pass = 模型→模板→回放 主线跑通 = 可进 Sim 实盘挂着跑。
