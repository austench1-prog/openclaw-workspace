## 0. 项目一句话定义

## 1. 项目边界（这个项目管什么 / 不管什么）

- **不管**：方向判断（上游独立模块，本项目前提，不在内）。

## 2. 项目构造 —— 七个组成部分（PART A~G）

### PART A — 策略模型源（地基，已有）
- **🔒 止损标定已定案（Chairman 2026-06-22 锁定）：15M=80点 / 1M=30点。经ATR确定，已完成的过程产物，后续直接用，不再作为"待定参数"讨论。**
- 内容：折扣区决策树（37叶）+ spec + ATR止损标定 + 注释。
- 输入：Chairman 图纸/原话。
- 输出：每条路径「剩几手 + 各手盈亏比/TP结构」的精确定义。
- 状态：**✅ 已有**（模型封板）。
- 衔接：是 PART B 的唯一数据源。

### PART B — 决策树 → ATM 参数反推（⭐ 关键缺口）
- 内容：从 PART A 抽出每条路径的「剩余仓结构」→ 翻译成 ATM Brackets（手数/SL/TP/保本/移动止损）。
- 输入：PART A 的路径定义。
- 输出：4 套 ATM 模板各自的「正确分批参数」。
- 状态：**❌ 缺口**（今天 DZ_15M_80x400 是拍脑袋的占位版，未反推）。
- 衔接：B 是 C 的地基；B 不对，C 全错。

### PART C — 4 套 ATM 模板（2×2，部分已建）
- 内容：{1:5策略, 完全按图纸1:1} × {15M/80止损, 1M/30止损}。
- 输入：PART B 反推结果。
- 输出：4 个 NinjaTrader 可识别的 ATM 模板 XML。
- 状态：**🟡 ①占位(待重做) ②③④待建**。
- 衔接：C 是被测对象（→D）+ 被风控对象（→E）。
- 已知能力边界：ATM 只管出场侧；加仓/分叉=手动（A路线锁定）。

### PART D — 测试 / 回放验证（待建）
- 内容：用历史数据回放，验证 4 套模板在真实走势下的表现。
- 输入：PART C 模板 + 历史行情数据。
- 输出：每套模板的 Pass/Fail + 表现记录 → 反馈修正 B/C。
- 状态：**❌ 待建**。
- ⚠️ Chairman 实操经验（已知约束，非搜索）：
  - 数据**只能一天一天单独下**，不能下区间。
  - 数据**时限有限**，很久以前的不一定有。
  - 期货**换月**，老合约可能已从下载窗口移除。
  - **最关键坑**：下载了 data 但 play 不了，因为产品已从窗口移除。
  - 用**时间跳/快进**操作（不是"一次跑完"）。
- 衔接：D 的结果决定 B/C 要不要改 → 决定能否进 Sim 实盘验证。

### PART E — 统一下单管理 + 整体风控（待建，Chairman 强调的核心）
- 内容：多笔手动加减仓散在一个 setup → 统一口径兜合规 + 风控。
- 输入：PART C 的所有下单动作 + 账户合规规则（Line1/Line2）。
- 输出：一个「过闸门」机制 —— 超 6手/MaxDD/无止损/过16:09 → 拦截或强平。
- 状态：**❌ 待建**。
- 两种形态：
  - A路线临时兜：模板预设 + 手动纪律 + 现有 FLATTEN_ALL 信号链 + 后台风控(MFF→Tradovate / TPT→CQG)。
  - B路线治本：中心化 risk gatekeeper（每单前检查，超限自动拦）。
- 衔接：E 罩在 C 之上，是所有下单的总闸门；真交易前必须有。

### PART F — DragonFileSignal 信号链 × ATM 配合（待设计）
- 内容：已跑通的信号链（龙哥→5000→signal.txt→策略→Sim101→Replikanto）怎么和 ATM 配合。
- 输入：已有信号链（✅活）+ PART C 模板。
- 输出：二选一或并存 —— ①信号触发进场→移交ATM管出场；②信号做"提醒中继"(Module C，只提醒不下单)，人据提醒手动挂ATM。
- 状态：**🟡 信号链✅活，配合方式❌待设计**（可能"再做一个策略配合"—Chairman原话）。
- 衔接：F 把"自动信号"和"手动+ATM"接起来；也连 FLATTEN_ALL 到 E。

### PART G — 远程操作能力（贯穿性基础设施，部分已验）
- 内容：Dragon 远程操作温总 PC 的 NinjaTrader 的能力。
- 状态：**🟡 SSH免密✅(读改XML可)；GUI操作(下载data/读指标/看回放)❌未验**。
- 衔接：D（下载回放数据）、PART B校准（读ATR指标）都依赖 G 的 GUI 能力 → **G 是个隐藏前置缺口**。

## 3. 关键缺口汇总（第2步 Tools 只针对这些找工具）
| 缺口 | 在哪个 PART | 缺什么能力 |

| ⭐ 决策树→ATM 参数反推 | B | 把模型路径翻译成 Brackets 的方法（人工/脚本？） |
| 4套模板正确化 | C | 依赖 B |
| 回放测试 | D | 下载历史数据 + 回放 + 记录的工具链；且要绕开"产品移除"坑 |

| 远程 GUI 操作 | G | Dragon 能否远程操作 NinjaTrader 界面（下数据/读指标） |

## 4. 依赖关系（地基→上层）
```
A(已有) ──> B(反推,缺口) ──> C(4模板) ──> D(回放测试) ──┐
                                          ├──> 修正回 B/C
G(远程GUI,前置) ──> D, B校准              │
E(统一风控) ─── 罩在 C 之上               ──> Sim实盘验证(三步骤第①步)
F(信号链配合) ─── 接 C 与 E
```
