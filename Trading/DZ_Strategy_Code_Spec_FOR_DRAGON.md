## 1. 策略是什么（一句话）

方向已经由上游判断决定（不在这个策略里）。

## 2. 完整价位公式（Stop = 30 点，R:R = 1:1）

```
已知：
  Entry   = 人为进场点（唯一的人为输入）
  Stop    = 30 点（固定）
  R:R     = 1:1（固定）

自动计算：
  STOP      = Entry - 30        ← 止损，全平出场
  LEVEL_25  = Entry - 15        ← 25% 折扣层（= Stop距离的50%）
  LEVEL_50  = Entry             ← 50% 折扣层 = Entry本身（第一笔进场点）
  TP        = Entry + 30        ← 止盈，卖一半

区间结构：
  [STOP] ----15点---- [LEVEL_25] ----15点---- [LEVEL_50/Entry] ----30点---- [TP]
    0%                   25%                        50%                      100%
```

**这就是全部。没有其他数字需要问任何人。**

---

## 3. 执行逻辑（状态机）

### 触发条件（全部 tick-by-tick 判断）

```
价格触碰 LEVEL_50（Entry）   →  进 1 手
                                 之后监控两条路径：

路径 A（碰25%）：
  价格跌到 LEVEL_25            →  加 4 手  → 共 5 手
  价格回升到 LEVEL_50          →  减 3 手  → 剩 2 手
  价格继续到 TP                →  卖 1 手  → 剩 1 手（底仓）
  价格跌到 STOP                →  全平 5 手（任何时候到STOP都全平）

路径 B（没碰25%，直接回升）：
  价格回升确认（未触碰LEVEL_25）→  加 3 手  → 共 4 手
  价格到 TP                   →  卖 2 手  → 剩 2 手（底仓）
  价格跌到 STOP                →  全平 4 手（任何时候到STOP都全平）
```

### 路径判断逻辑
```
进1手之后：
  if 价格 <= LEVEL_25:
      → 路径 A（加4手）
  else if 价格 >= TP（未曾触碰LEVEL_25）:
      → 路径 B（加3手）
  
  STOP 是永远有效的安全网，任何路径下触碰即全平。
```

## 4. 手数汇总

| 时点 | 路径A 手数 | 路径B 手数 |
|---|---|---|
| 进场后 | 1 | 1 |
| 碰25% / 回升确认后 | 5 | 4 |
| 回到50%减仓后（路径A） | 2 | — |
| 到TP卖一半后 | 1（底仓） | 2（底仓） |
| 到STOP | 全平 | 全平 |

## 5. 信号协议（SETUP 信号）

```
人发：ENTRY|NQ|<entry_price>

策略收到后自动计算：
  STOP     = entry_price - 30
  LEVEL_25 = entry_price - 15
  LEVEL_50 = entry_price
  TP       = entry_price + 30

之后完全自动运行，不需要任何后续信号。

紧急：FLATTEN_ALL → 全平所有仓位，重置状态
```

## 6. NinjaScript 实现要点

- `Calculate.OnEachTick` — tick-by-tick 判断
- `EnterLong(qty, "name")` — 加仓
- `ExitLong("name", "", qty)` — 减仓（指定手数）
- `SetStopLoss(CalculationMode.Price, stopPrice)` — 全仓止损
- TP 用 `OnBarUpdate` 手动监控（因为要部分出场，不能用 SetProfitTarget）
- 状态机：Idle → Armed → Entered → PathA/PathB → Complete/Stopped

---

## 7. 第二笔交易区域（区域B）

总裁设计是：区域A完成后，剩余底仓继续持有，等待区域B出现。
区域B = 人再发一次 ENTRY 信号，系统用同样公式重新计算一套价位，独立运行。
**两个区域互不干扰，各自独立结算。**
