## 一、它是什么(一句话)
把 Dragon 系统在后台对市场的判断,**可视化成一排灯 / 彩球**,让 Chairman 一眼看到
"系统现在发现了哪些机会",点选后看细节(评分卡),再决定下不下单。
它是**人机沟通的前端 / 系统判断的显示器**。

**核心痛点:** 否则 Dragon 在后台算一堆东西,Chairman 根本不知道系统在想什么。
灯亮 = 系统看到了;灯灭 = 没机会。让判断"可见"。

---

## 二、每个灯/球代表什么(三个维度)
1. **时间框架**:4H / 15min / 1min
2. **方向**:多 / 空
3. **策略类型**:A 类(如 FVG)/ B 类(如引线 sweep)/ C 类...

一个灯 = (时间框架 × 方向 × 策略类型) 的一个组合是否出现 setup。

---

## 三、灯的状态怎么表达(细节)
- **灭** = 没有评估出任何 setup
- **亮** = 系统发现一个符合该策略的 setup
- **颜色/亮度 = 质量 + 风控状态**（草案，见下“绿灯硬定义”）：
  - **绿色常亮 = 已通过风控的可下单信号（= Gatekeeper ALLOW）** —— 这是硬定义，不只是质量高
  - 黄色 = 评分中 / 接近但未过风控
  - 闪烁 = setup 正在形成中，未完全确认
- **点击灯** → 弹出该 setup 的**评分卡**:
  - 必要条件 ✓ 清单
  - 次要条件得分
  - 止损位 / 止盈位 / 盈亏比
  - 对应参考胜率(来自胜率库)

## 四、交互流程("拍卖"模式)
```
系统后台实时扫描各 (时间框架×方向×策略) 组合
→ 发现 setup → 对应的灯亮起(颜色=质量)
→ Chairman 扫一眼面板,看哪些亮了
→ 点感兴趣的灯 → 看评分卡细节
→ Chairman 决定:下单 / 不下
```
像拍卖:喜欢哪个按哪个,按下后再一起决定要不要下。

## 四半、绿灯的硬定义 + 一键下单(2026-06-14 Chairman 补充,关键)

**绿灯 ≠ "质量高",绿灯 = "已通过风控(仓位管理)的可下单信号"。**
- 绿灯亮 = 这个单下下去**不会冲击风控**(不超 Max DD / DLL / Max contracts,不违反 Line 1)。
- 绿灯灭 = 要么没机会,**要么下了会突破风控** → 不该亮。
- 即:灯的颜色不只看"机会好不好",还要看"下了合不合规 / 超不超风险"。

**一键下单两个层级:**
1. **一键下"所有绿灯"** -- 因为所有绿灯作为一个整体已过风控验证:全下也不冲击风控 → 可放心一键全下。
2. **单独下某一个绿灯** -- 就算只下一个,它也是单独通过风控的,在风险之内。

**关键约束:**
- 一键全下的前提 = "这批绿灯加起来仍在风控内"。加起来会超 → 不该都亮成可一键状态。
- **风控是最高否决权**:市场机会再好,但风控已容不下任何一单 → 所有灯都不亮。

**用意(为什么要这个设计):**
- 特殊行情(急拉/急跌)时,来不及一个个下 → 一键全下解决速度。
- 但一键全下最大风险 = 盲目、超风控 → 用"绿灯=已过风控"这个定义让一键下单天然安全 → 既快又不失控。

**与 MATS 的衔接:** 绿灯 = Gatekeeper 判 **ALLOW**。这不是新东西,是把已有 Gatekeeper(ALLOW/BLOCK/REDUCE_SIZE)的判断"点亮"出来。风控引擎依赖:凯利 f + 单笔硬帽 + 账户 Max DD/DLL/contracts + Line 1。

## 五、可行性评估(诚实)

| 层 | 内容 | 可行性 |
|---|---|---|
| 后台计算 | 实时算各时间框架/策略的 setup 评分 | ⚠️ 依赖策略先量化(评分卡规则要先定死) |
| 数据 | 实时行情喂给计算 | ✅ 可行(IBKR / 数据源) |
| 前端面板 | 一排灯/球可视化 + 点击看卡 | ✅ 可行(网页面板,Dragon 能做) |

**最大依赖(关键):**
- 漂亮的前端容易;难的是后台"灯该不该亮、什么颜色"的判断逻辑。
- 而那正是**策略量化 + 回测胜率库**要先完成的事。
- 结论:**面板是策略方法论的"显示器",不是独立的东西。**
  策略没量化,灯就没有亮灭依据 → 面板天然排在策略量化之后。
- 现在记录想法、设计形态,完全合理;实际开发等策略量化完成。

## 六、与已有讨论的关系
- 它是"Dragon 提示、Chairman 拍板"盯盘模式的**可视化前端**。
- 点击灯看到的评分卡 = 之前定义的"策略评分卡"(必要条件/次要条件/止损止盈/盈亏比)。
