## 核心拓扑结构

| 节点 | 角色 | 位置/工具 | 职能 |
|---|---|---|---|
| **龙哥** | 系统总工程师/总裁助理 | Mac mini / Python | 环境监控、SSH安全、熔断、净值报表 |
| **NotebookLM (ls)** | Logic Source / 真值来源 | Google Cloud | 解析原始合同，输出准确规则JSON，审计合规逻辑 |
| **Agent Teams** | 决策与执行中枢 | OpenClaw / Claude API | 接收规则，执行下单，监控DD，16:00强平 |
| **终端执行层** | 交易执行节点 | 温总 / NinjaTrader | 订单入场，Replikanto跟单 |

---

## 四大刚性约束（大规则覆盖小规则）

1. **完整交易日准入** — 非完整交易日全天锁定
2. **16:00 硬性强平** — 无论平台规则，ET 16:00 强制 FLATTEN_ALL
3. **动态水位熔断** — 距 Floor 剩 $100-200 时龙哥触发熔断
4. **强制止损单** — 无止损单被执行层拒收

## 第一阶段部署路径

### Step 1：ls 逻辑源建立
- 把 Apex、MFF 原始合同和 Dashboard 截图喂给 NotebookLM
- 输出"黄金标准规则表"作为 Agent 底层校验库

### Step 2：小账户实战先遣队
- 最小规模考试账户（$25K/$50K）开启全自动下单
- 验证 16:00 强平 + Agent 与 NinjaTrader 同步

### Step 3：龙哥双重保障
- **硬件侧**：监控温总延迟，>200ms 自动降频/暂停
- **信息侧**：下单前基于 ls 规则做最后核对

## NotebookLM 的角色（ls）

- 不参与执行，只负责信息准确性
- 彻底消除"感觉规则更新了"的问题
